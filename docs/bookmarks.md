# Bookmarks design

## Purpose and scope

- This note designs row 64 (bookmarks) of `docs/features.md` and queue tasks III.16 to III.20 and III.25 in `docs/plan.md`. Row 65 and tasks III.21 to III.24, live folders, were removed (Live sources). Every label it adds follows Persona rule 7 of `docs/windows-personas.md`: a Persona named with one of its spaces shows as "Persona / Space", as the space header, the window title, and the bottom bar's tooltips already show it.
- Bookmarks: pinned tabs, favorites, and the folders that hold pinned tabs become Arch's bookmarks. Each keeps a saved page to return to and can unload and reload its page. Folders nest, and a Bookmarks menu lists them.
- Excluded: a bookmarks bar, because nothing sits above the page (Approach in `docs/plan.md`); a bookmark manager window, because the sidebar, the Bookmarks menu, and the palette, which already lists pinned tabs, cover it; custom icons for folders and tabs; and muting, which Arch's tabs do not have.
- Arch runs no server and no service of its own for any of this. Nothing here uses a private API or needs a flag on `flags://`.

## Facts this design relies on

### Arch today

- A pinned tab is a tab with `isPinned` and, since III.16, a saved page (`Tab.savedPage`), which `session.json` keeps beside its current address and title. Closing it unloads it to its saved page (Unloading, III.17); Delete Tab moves it to the closed list, whose record keeps the saved page.
- A favorite's `url` and `title` already act as its saved page: Close ends the favorite's tab, and the next click opens the favorite's address. `savedFavoriteTabs` keeps the last session's tabs as records (address, engine, page state) until their favorites are clicked.
- A restored tab has an `UnloadedWebContents` stand-in until a window first shows it (III.14), and so does a tab whose page unloaded (Unloading, III.17) until a window next shows it. A load on the stand-in replaces its saved page without loading.
- A tab's page state is its engine's `restorableState`: on WebKit, `interactionState`, which brings back the back list and the scroll position. The Chromium adapter keeps none (`restorableState` is nil), so a restored Chromium tab loads its last address without its back list (regression check 58).
- Leaving a page: Chromium's `tryToClose` runs the page's `beforeunload` handlers, which ask through `runBeforeUnloadPanel`. WebKit's agrees at once, because WebKit has no public way to run them. Neither engine tells the app whether a page holds unsaved input; both run page scripts in every frame (`EnginePageScript`).
- `EngineWebContents.isCapturingMedia` follows WebKit's public `cameraCaptureState` and `microphoneCaptureState` on `WKWebView` (macOS 12), which have no counterpart for screen sharing, and CEF's `CefDisplayHandler::OnMediaAccessChange(browser, has_video_access, has_audio_access)` (III.17).
- Remembered permissions (`permissions.json`) keep Allow and Don't Allow per origin and type, notifications among them. A Chromium page's notifications come from the page (row 40), so they stop while its tab has no page.
- `BrowserSession.closeTab(_:reason:)` closes a tab as `TabCloseAction` decides for its kind and the reason (III.17, Unloading). Its callers: `requestCloseTab` once the page agrees (⌘W, the row's button, Close Tab, Close Other Tabs, which skips pinned tabs, and a small window's close); `tab.didClose`, when the page closes itself or the engine closes its crashed page; `SessionWebExtensionHost.close`, for an extension's `tabs.remove`; `didOpenOnlyDownload` and the start of the download it waits for, for a tab that only pointed at a file, which a restored tab (`isRestored`) reaches without fetching the file; `deletePersona`, which closes each of the Persona's tabs without asking; and archiving, which closes only unpinned tabs. `requestDeleteTab` closes a pinned tab into the closed list. The closed list keeps 100 records.
- Folders nest up to four levels in a space's pinned or open list (Nested folders, III.18). Browser import joins nested folder names into one level ("Work / Docs"). Folder rows drag among the rows, into other folders, and to another space's symbol (III.19), and Move to Space moves a folder or tab to another space of any Persona (`docs/windows-personas.md`, Moving tabs between spaces).
- `Tab.isUnread` puts a dot on the row of a tab that a page opened in the background; selecting the tab clears it. It is not saved.
- `session.json` is at version 16: the session fixes took version 13 to seal page state (`SessionStateSeal`), III.16 version 14 for saved pages, III.18 version 15 for folder parents, and III.22 version 16 for live folders, which this build reads as ordinary folders (Live sources). Each step that adds fields takes the next free version number when it lands and migrates through `normalized()`. VII.12 adds `TabFolder.agentSessionID`, which is not encoded, for agent folders among the open tabs.
- `FaviconLoader` caches icons by icon address, shares concurrent downloads, and clears its cache once it holds 200. At every launch `restoreTabs` has each restored tab's stand-in request its site's `/favicon.ico` (`loadSiteIcon()`), and a load on a stand-in requests the new site's.
- Browser import counts an address as already pinned in a space by each pinned tab's current address (`tab.url`) and, since III.16, its saved page, and merges an imported folder into a pinned folder of the same name (`SidebarImport`).
- The bottom bar lists every Persona's spaces, and each symbol's tooltip and accessibility label is `BrowserSession.displayedPlace(ofPersona:space:)`, "Persona / Space" with two or more Personas, or the space's name alone with one (`SidebarBottomBar`). New Persona gives every new Persona a space named Personal.

## Decisions

Code comments and documents cite these rules by number, as in "bookmark rule 4".

### Bookmark rules

1. Pinned tabs, favorites, and the folders that hold pinned tabs are the bookmarks. Arch keeps no separate bookmark store, bar, or manager. Import, sync, and the palette already treat them as bookmarks; one place to organize them is enough.
2. Each pinned tab keeps a saved page: an address and a title. A tab saves the page it shows when pinned (Pin Tab, a drop among the pinned tabs or into a pinned folder), or the first address its page reports if it had none. Unpinning clears the saved page. A reopened pinned tab keeps the saved page from its record. Browser import gives an imported pinned tab its address and title. Use Current Page as Saved Page and Edit Saved Address… change it. A favorite's address and title are its saved page.
3. A tab is on its saved page while its address equals the saved one, ignoring the fragment, `http` against `https`, the host's case, a leading `www.`, and a trailing slash. It is on its saved site while its host equals the saved host the same way. Go Back to Saved Page is offered whenever a pinned tab or a favorite's tab is off its saved page; the row offers it only while the tab is off its saved site. A pinned web app changes its address constantly, and redirects and returns from sign-in pages would otherwise mark the row.
4. Closing a pinned tab unloads it: once its page agrees to leave, the page closes and the tab keeps its place with a stand-in at its saved page, without page state. This applies to ⌘W, the row's button, Close Tab, an extension's `tabs.remove`, and the page's `window.close()`; Unloading lists every path that closes a tab. Unloading adds nothing to the closed list or the tab close log, and, as when a favorite's tab ends, ⌘Z then reopens none of the tabs closed before it. Delete Tab removes a pinned tab into the closed list. A favorite's Close ends its tab, as today. A bookmark outlasts its page, and returning to it starts at the saved page.
5. Pinned tabs and favorites' tabs that no window shows unload automatically and keep their place. The stand-in keeps the address, title, icon, and the engine's page state: a WebKit tab comes back where it was, with its back list; a Chromium tab, whose adapter keeps no page state, loads its last address without its back list, as after a relaunch (open decision 5). The archive timer unloads those inactive for the hours set in Settings ▸ Sidebar (the Unload pinned tabs and favorites picker: Never, 1 hour, 12 hours, 1 day, or 1 week; 12 hours by default). While that setting is not 0, memory pressure reported by macOS (`DispatchSource.makeMemoryPressureSource`) also unloads every tab that no window shows, open tabs included: at a warning those inactive for 30 minutes, at critical all of them. A tab stays loaded while it plays sound or media, shows a video in picture in picture, also paused or muted, since the system's window closes with the page, uses the camera, microphone, or screen, holds text the user typed since its page loaded, shows a site allowed to post notifications, has a prompt waiting, has downloads that need its page, is in a small window, opened a page that a window shows, as a sign-in popup that reports back to it, or sits in an agent folder (VII.12). Sound counts only from audio and video elements in the page's documents, which both engines' media scripts watch; Web Audio and an element outside the document, as many games and some players use, keep no tab loaded (risk 8). A call, a page the user is writing in, and a web app that posts notifications must not stop because the user looked elsewhere. Automatic archiving also leaves ordinary background tabs open while they have reported typed input, playback, picture in picture or active capture. A saved session counts those tabs as recently active. An automatic unload answers a Chromium page's `beforeunload` question with Stay, without a card, which keeps the page. WebKit cannot run those handlers, so on WebKit the typed text exclusion keeps drafts, as it does on Chromium pages without a handler.
6. Folders nest up to four levels in the pinned and open lists. A folder lists its folders first, then its tabs, as each list does. Agent folders hold no folders. Bookmark collections nest, and four levels at 12 points each leave the 240-point sidebar room for names. Browser import keeps joining nested names into one level, as `docs/import-browsers.md` describes: its record finds a folder by the source folder's ID, but merging by name, used when the record finds none, compares the joined name, which keeps source folders of the same name in different places apart.
7. The Bookmarks menu in the menu bar lists the window's Persona's favorites and every space's pinned folders and tabs, one submenu per space. With two or more Personas, the spaces group by Persona and each submenu is titled "Persona / Space", while the favorites, which belong to the whole Persona, are headed by the Persona's name alone (Persona rule 7).

## Saved pages (III.16, built)

- While a tab is dragged, a row of the other list, pinned or open, takes it as soon as the pointer reaches it, before that row in its upper half and after it in its lower half (`SidebarTabSlot.placement`). A pinned tab released on any open tab's row, on the New Tab row, or in the empty space below it thus becomes an open tab and loses its saved page, as Unpin Tab makes it, keeping its page or its stand-in. Where no row under the divider takes it, as over an agent's folder, which takes only its agent's tabs, or a collapsed folder's selected tab, it goes before the next open tab outside folders, or to the open list's end, and unpins the same way (`SidebarTabSlot.unpinning`). Released on the divider, which ends the pinned list, it stays pinned. An open tab released on the divider or a pinned tab's row pins with the page it shows as its saved page, as Pin Tab pins it.
- The pinned tabs stay in place under the space's header, in an area at most half the space's page high that scrolls on its own, while the open tabs scroll below the divider. A row far down a long list reaches the other list's rows by scrolling: held within 32 points of the top or bottom of the pinned or open area's visible part, a dragged tab or folder row scrolls that area toward that end, faster nearer the edge, until the pointer leaves the band, the list reaches its end, or the drag ends (`DragAutoScroll`). A drag that starts in a band scrolls only once the pointer leaves it or moves 8 points toward its edge, so the row grabbed there can move a place first. The list moves in whole pixels. The slot and the drop targets follow the rows that pass under the still pointer, whether this scroll or a mouse's wheel moves them, and the slot's last place moves with them by the distance the list moved (`SidebarReorderHover.scrolled(by:)`), so release commits the place the slot shows. A slot scrolled out of sight takes the released row only to the list's edge, where the row fades out. Favorites and space symbols do not scroll the list.
- `SavedPage` holds an address and a title. `Tab.savedPage` follows bookmark rule 2: `isPinned` turning on sets it from the tab's address and page title, turning off clears it, and a pinned tab without one takes the first address its page reports, with an empty title. `restore(_:folderID:)` takes the saved page from the record, and `takeImport(_:)` from the imported address and title.
- `URL.isSamePage(as:)` and `URL.isSameSite(as:)` compare according to bookmark rule 3. `Tab.isOffSavedPage` and `Tab.isOffSavedSite` use them; a favorite's tab compares with its favorite's address, which the session supplies.
- Go Back to Saved Page loads the saved address in the tab, or the favorite's address in its tab. For a tab without its page, the stand-in takes the saved page without loading, as any load on it does.
- Use Current Page as Saved Page takes the tab's address and page title. For a favorite it changes the favorite's address and title; it is disabled while another favorite of the Persona has that address.
- Edit Saved Address… opens an `NSAlert` sheet on the window, as New Persona does, with a text field prefilled with the saved address. An address that `BrowserSession.url(forInput:)` rejects changes nothing. A tab without its page moves its stand-in to the new address. For a favorite, Edit Favorite… has Name and Address fields.
- Copy Address copies the tab's current address, or the favorite's, as a URL and as text. Duplicate opens and selects a copy after the tab, in the same list and folder, at its current address in its engine; a pinned copy keeps the original's saved page.
- Where: the tab row's context menu (Go Back to Saved Page, Use Current Page as Saved Page, Edit Saved Address…, Copy Address, Duplicate), the favorite tile's (Go Back to Saved Page, Use Current Page as Saved Page, Edit Favorite…, Copy Address), and the Tab menu (Go Back to Saved Page, Use Current Page as Saved Page, Edit Saved Address…, acting on the selected tab). They have no default shortcuts; Settings ▸ Shortcuts can assign one.
- While a tab is off its saved site, its row shows a back button (`arrow.uturn.backward`) before the close button when under the pointer, with a tooltip naming the saved address.
- Decisions made while building it:
  - A saved page's title is the page's title as the tab reports it, which is empty for a page that has shown none yet, as for a tab pinned before its page reported an address. A saved page taken from the first address a page reports starts with an empty title, since the tab's title is still the previous page's then. An empty saved title takes the first title the page shows at the saved address.
  - Edit Saved Address… keeps the saved title while the new address names the same page and leaves it empty otherwise, so the page's own title fills it once the tab shows it there. Text that `url(forInput:)` rejects beeps. Edit Favorite… keeps the name when its field is left empty, and refuses, with a beep, an address that another favorite of the Persona has, as Use Current Page as Saved Page does, since a Persona's favorites come once per address (`addFavorite(_:)`).
  - The favorite commands act on the favorite's open tab. A tab saved for the favorite from the last session, which has no page until the favorite's first click, counts once that click opens it. The tile's Go Back to Saved Page and Use Current Page as Saved Page come from a view that observes the tab (`FavoriteTabSavedPageItems`), because the grid redraws only with the window's selected tab and the session's lists, so a page change in the tab while another tab is selected would otherwise leave the menu as it was.
  - A tile drops an icon that arrives after its favorite moved to another site, so the old site's icon cannot replace the new one.
  - The context menus show Go Back to Saved Page only while it applies; the Tab menu keeps it and disables it otherwise, and also while an internal page or the preview panel covers the tab, as Home does. The Tab menu's Edit Saved Address… is for pinned tabs only; a favorite's tile has Edit Favorite….
  - Duplicate does not copy the user's name for the tab, and the window whose row it came from selects the copy.
  - A tab row's menu keeps the Page Address plugin's own Copy Address in that plugin's section, which can copy a Markdown link; the row's Copy Address copies the address alone and does not depend on the plugin.
  - Code: `SavedPage.swift` holds `SavedPage`, the comparisons, the tab's saved page methods (`isOffSavedPage`, `isOffSavedSite`, `goBack(toSavedPage:)`, `useCurrentPageAsSavedPage()`, `setSavedAddress(fromInput:)`), the favorite's (`Favorite.usingCurrentPage(of:among:)` and `edited(name:address:among:)`, which give the changed favorite or nil), and the session's saved page commands; `BrowserSession.duplicateTab(_:)` and `updateFavorite(_:_:)`, which change the session's lists, live in `BrowserSession.swift`. Browser import gives an imported pinned tab its saved page through `Tab.takeImport(_:)` and reads each space's tab through `SidebarImport.Sidebar.TabState.init?(_:)`, so tests check both on `PageStub` tabs. `Tab.isPinned` saves and forgets the saved page as it changes, so every way of pinning and unpinning follows bookmark rule 2.

## Unloading (III.17, built)

- Closing a pinned tab (bookmark rule 4) asks the page as closing does, then follows the closing steps without removing the tab: a window that shows its page in full screen leaves it, its prompts end, it leaves its split view, each window that selected it selects another tab as after a close (window rule 3, `BrowserSession.tabToSelect(after:opener:splitNeighbor:among:spaceID:isShownInAnotherWindow:)`), and `retire` closes the page, keeping it on a blank page while its downloads need it. The tab then holds `UnloadedWebContents(url:title:engine:state:)` at its saved page, or at its address without one, without state, which requests the site's icon. Its first load at the saved page counts as a visit.
- `TabCloseAction.of(_:reason:)` decides what a close does: unload for a pinned tab, end for a favorite's tab, and close for any other tab, into the closed list unless it only pointed at a file. Forget for an unkept agent tab (close without the closed list or the tab close log, `docs/agents.md` decision 10) joins with VII.12. Every path that closes a tab goes through `BrowserSession.closeTab(_:reason:)`, or through `requestCloseTab(_:)`, which asks the page first (`whenPageAgreesToLeave`): while the tab's leave-page card shows, that card is the question and the tab only comes forward, and otherwise the tab's prompts end before the page is asked (`TabPromptQueue.endForClose`):
  - ⌘W, the row's button, Close Tab, Close Other Tabs, and a small window's close (`requestCloseTab`), the page's `window.close()` and a crashed page that the engine closes (`tab.didClose`), an extension's `tabs.remove` (`SessionWebExtensionHost.close`), and a plugin's `closeTab(_:)` (`SessionPluginBrowserHost.closeTab(_:cause:)`): the action for the tab's kind, so an extension unloads a pinned tab. Once the page, an extension, or a plugin closes a tab into the closed list, ⌘Z reopens none of the tabs the user closed before, so it never reopens their tab in place of the user's.
  - A tab that only pointed at a file (`didOpenOnlyDownload`, and the download's start): a pinned tab unloads to its saved page and keeps its place; a favorite's tab ends; any other tab closes without the closed list. Unloading clears `isRestored`, so opening the tab again downloads the file.
  - Delete Persona (`deletePersona`, reason `persona` in the tab close log): the Persona's pinned and open tabs close into the closed list without asking, and its favorites' tabs end. Agent tabs follow with VII.12.
  - Archiving closes only unpinned tabs, so it reaches no pinned tab.
- ⌘Z reopens only a tab that joined the closed list. After an unload or a favorite's end, ⌘Z reopens none of the tabs closed before it, rather than an older tab in its place. A close whose page agreed only after the tab had closed another way does nothing and counts for neither (`closeTab` returns whether the tab was still open).
- Delete Tab, in a pinned tab's context menu, asks the page, then closes the tab into the closed list (`requestDeleteTab(_:)`); ⌘Z reopens it pinned in its folder with its saved page.
- Automatic unloading (bookmark rule 5): `TabUnloading.tabsToUnload(_:now:after:pressure:)` picks from `UnloadCandidate` values (ID, kind, last activation, and exclusions) without session state, so tests drive it directly. Every 30 minutes the archive timer calls it, after archiving, with the hours that Settings ▸ Sidebar saves under `ARCHUnloadAfterHours` (12 by default, 0 for never); `MemoryPressureMonitor`, a `DispatchSource.makeMemoryPressureSource` on the main queue, calls it with the event's level. Candidates are loaded tabs that no window shows. A tab's last activation is when a window last selected it or stopped showing it, or the archive timer last found it shown, or found it with a draft, playback, picture in picture or capture.
- An automatically unloaded tab, pinned, open, or a favorite's, keeps its place, folder, split view, and ID, and a favorite's tab stays its favorite's, whose tile then dims as a favorite without an open tab does, until a window shows the tab again (`BrowserSession.hasOpenPage(_:)`). Its stand-in keeps its address, title, icon, and its engine's page state (`Tab.unloadKeepingPage()`), which a Chromium page lacks; the page takes its host's remembered zoom again once it loads. Nothing joins the closed list or the tab close log, and a window loads the page again as it shows the tab, each pane as it shows a split view.
- The exclusions of bookmark rule 5 (`UnloadExclusion`) come from:
  - Capture: `EngineWebContents.isCapturingMedia` (`docs/engine-protocol.md`). The WebKit adapter reads `cameraCaptureState` and `microphoneCaptureState`, counting active and muted; the Chromium adapter takes CEF's `OnMediaAccessChange` through the bridge's `cefBrowserDidChangeMediaAccess(video:audio:)`; the stand-in reports false.
  - Typed text: `TabUnloading.inputScript`, a page script in a world of Arch's own (`arch.unloading`) that runs first in every frame's document at document start. The main frame's new document sends `start`, and each frame sends `typed` on its first trusted input and again when its edited document returns from the back-forward cache. `Tab.hasTypedInput` turns on with `typed` and off with `start`, when a main document commits, and with another web contents. On Chromium the page shares the script's world, so a page could at most keep its own tab loaded and out of automatic archiving.
  - Notifications: the session's remembered permissions, for the origin of the tab's address.
  - Picture in picture: `EngineWebContents.isInPictureInPicture`, which also keeps a paused video and one muted from the start, which the sound exclusion misses, so the system's window stays open. The Chromium adapter reports it from the engine's start of picture in picture until AVKit has finished stopping (`ChromiumPictureInPicture`). WebKit's media script reports each document's `document.pictureInPictureElement` and its videos' `webkitPresentationMode` at its media events and at `enterpictureinpicture`, `leavepictureinpicture`, and `webkitpresentationmodechanged`, so a video inside a shadow root counts only through `pictureInPictureElement`; the stand-in reports false.
  - Sound and media (`isAudible` and the media session's playback state, which the media scripts learn from the document's `video` and `audio` elements, so Web Audio and elements outside the document go unseen), a prompt that waits or shows as a card (`TabPromptQueue.hasPrompt(for:)`), downloads (`closingStopsDownloads`, or a file the tab waits to download), a small window, open developer tools, which unloading would close, and an opener: a tab whose page opened one that a window shows (`Tab.opener`), so a sign-in popup's `window.opener` stays alive and its `window.close()` returns to the tab. Agent folders join with VII.12.
- The automatic path sets `Tab.answersBeforeUnloadWithStay` for its call to `tryToClose`, so a Chromium page's leave-page question returns Stay without a card and the page stays loaded until the next try. A close the user asks for meanwhile clears it, so the page's question shows for that close, and the page's answer reaches only that close. WebKit's `tryToClose` agrees at once, so on WebKit the typed text exclusion is what keeps a draft.
- Rows of tabs without a page show their icon and title dimmed (`SidebarDimming.unopened`), as rows of tabs restored from the last session do, so the sidebar shows which tabs have pages; a selected row, whose tab a window loads, is not dimmed. A pinned row's close button, under the pointer, is a minus (`minus`) with the tooltip Unload Tab, shown only while the tab has its page. Settings ▸ Sidebar has the Unload pinned tabs and favorites picker (Never, 1 hour, 12 hours, 1 day, or 1 week; 12 hours by default) below the archive picker.
- Decisions made while building it:
  - A favorite's tab unloads into a stand-in in its favorite instead of moving to `savedFavoriteTabs`, as a pinned tab keeps its row: the tab keeps its ID, title, and icon, the tile's menu items that observe it keep working, and quitting saves it as it saves any favorite's tab.
  - Close on a pinned tab without its page unloads it again to its saved page, so Close also takes an automatically unloaded tab back to its saved page.
  - The selection after any close or unload passes over pinned tabs without their page, which are closed bookmarks: ⌘W never loads a pinned page that the user closed or has not opened since launch, two pinned tabs whose saved pages are files cannot download each other in turn, and with only such tabs left the window shows the empty page. An open tab without its page, as after a relaunch, is still chosen.
  - Settings ▸ Sidebar's footer says, while the delay is Never, that tabs also keep their pages under memory pressure, and otherwise that some sounds keep no tab loaded.
  - Open developer tools keep a tab loaded, as a window of their own would close with the page.
  - The closed record of a close (`TabCloseAction.closedRecord(of:)`) reads no page state, which the closed list does not keep.
  - Code: `TabUnloading.swift` holds `TabCloseAction`, `UnloadPressure`, `UnloadExclusion`, `UnloadCandidate`, `TabUnloading` (the hours setting, `unloadAfterHours(in:)`, `tabsToUnload`, the input script and its events), `MemoryPressureMonitor`, and the tab's two stand-in methods, `unloadToSavedPage()` and `unloadKeepingPage()`. The session's side, `closeTab`, `requestCloseTab`, `requestDeleteTab`, the unload in place, the selection after a close (`tabToSelect`, static so tests drive it), and `unloadInactiveTabs(pressure:)` with its candidates, is in `BrowserSession.swift`.

## Nested folders (III.18 and III.19 built)

- `TabFolder.parentID` names a folder of the same space and list. `FolderTree`, built from the session's folders and tabs, provides each list's rows with their depths, each folder's level, ancestors, and descendants, and the allowed moves. The session and the views ask it instead of walking `parentID`.
- Rows: a folder's row is indented 12 points for each folder that holds it, and its tabs one level further. A folder lists its folders, then its tabs. A collapsed folder hides everything inside it but the selected tab, which shows one level in from the collapsed folder; a dragged tab also keeps its row there until release.
- Menus: a folder's context menu gains New Folder Inside (disabled at the fourth level), Move to Folder, and Move Out of Folder. Move to Folder, for folders and tabs, is a submenu that mirrors the tree: a folder containing listed folders is a submenu whose first item moves into that folder. It offers only the moves `FolderTree` allows: a folder not into itself or a folder inside it, not past the fourth level, and not to another space or list; a tab not to another space, taking the target folder's list. The agent cases add agent folders (Interactions with other features ▸ Agents).
- Delete Folder keeps everything inside: its folders take its place in its parent, and its tabs go first among its parent's tabs, or among the list's tabs outside folders at the top level, as today.
- Deleting a space moves its folders and their tree to its neighbor. `FolderTree.isInCollapsedFolder(_:)` checks every ancestor.
- Dragging (III.19): `SidebarDragItem.folder` lifts a folder row like a tab row; its contents stay hidden until release, and the list keeps their height below its end, so that a list scrolled to its end does not scroll back and move other rows under the pointer; held near the list's top or bottom, it scrolls the list as a dragged tab does (Saved pages), but not into that kept height. Between rows, it takes that place at that level; over another folder's row, which lights up with a light haptic, it goes inside at the end of its folders on release; over another space's symbol of its Persona, it moves with its contents to the end of that space's folders in the same list. `FolderTree.dropTarget(for:at:)` decides each place in the list, and where it refuses one, nothing moves and the row returns to its slot on release. A tab dropped on a folder's row at any level joins that folder, as `canMoveTab(_:into:)` allows.
- Decisions made while building it:
  - A tab's Move to Folder lists every folder of its space, nested: the pinned list's tree, then the open list's after a divider, since a tab takes the list of the folder it moves into. Its own folder stays in the menu, without a first item, while it holds folders the tab can move into. A folder's Move to Folder lists only its own list and leaves out its parent.
  - A folder that Move to Folder shows as a submenu repeats its name as the submenu's first item, followed by a divider, because choosing a submenu's own title does nothing in a macOS menu.
  - Move to Folder puts a folder last among the target's folders, as a tab goes last among a folder's tabs. Move Out of Folder puts a folder right after the folder it leaves, and a tab first among the tabs one level up, as Remove from Folder put it first among the tabs outside folders; the tab's item is now named Move Out of Folder, like the folder's.
  - Add to New Folder makes the folder where the tab is, inside the tab's folder, as the Finder's New Folder with Selection makes it beside the selection, and is disabled in a folder at the fourth level rather than putting the folder elsewhere.
  - New Folder Inside and Add to New Folder expand the folders that hold the new folder, so its name field shows.
  - `normalized()` lifts a folder at the fifth level to the top of its list with what it holds, rather than dropping the folders below it, so no tab loses its folder.
  - Browser import's merge by name matches a pinned folder of the space at any level, as its record matches a folder wherever the user moved it.
  - Code: `FolderTree.swift` holds `FolderTree`: the structure (`folder(_:)`, `topFolders`, `subfolders(of:)`, `tabs(inFolder:)`, `tabs(inside:)`, `tabs(in:pinned:)`, `ancestors(of:)`, `descendants(of:)`, `level(of:)`, `isInCollapsedFolder(_:)`), `Row` and `rows(in:pinned:hidingContentsOf:showingInCollapsedFolders:)`, `MoveTarget` and the checks `canAddFolder(inside:)`, `canMoveFolder(_:into:)`, and `canMoveTab(_:into:)`, the drag's `DropPosition`, `DropTarget`, `dropTarget(for:at:)`, and `canMoveFolder(_:to:)`, the changes `deleteFolder(_:)`, `moveFolder(_:into:)`, `moveFolder(_:to:)`, `moveFolder(_:toSpace:)`, `moveFolderOut(_:)`, and `moveTabOut(_:)`, and `repairingParents(of:)`. Move to Folder and the drag share the private check `canHold(_:in:)`. The session's `folderTree` builds one from its lists, and its folder commands apply the tree's changes to its lists; `canMoveFolder(_:toSpace:)` is the session's Persona guard for a space's symbol. `MoveToFolderMenu` in `TabFolderRowView.swift` draws the submenu for folder and tab rows. `SpaceTabsView` starts folder and tab drags, finds the `DropPosition` under the pointer from the rows' frames, and applies the target; `TabDragLayer` in `SidebarDragState.swift` draws a lifted folder row as it draws a tab row.
- Decisions made while building the drag (III.19):
  - The rows make room for a dragged folder, as they do for a dragged tab, instead of a line marking where it would land: each place between rows is a move the tree allows, so the slot shows the result, and release settles the row there. A place is always before a folder or at the end of a folder's folders, never after a folder, since the rows after an expanded folder are its contents: moving there would put the slot below them and leave the pointer over them, which would move the folder again.
  - The upper third of a folder's row places the dragged folder before that folder, and the rest takes it into the folder, since going into a folder is the commoner aim. A tab's row places it last among the folders of the tab's folder, since a folder lists its folders before its tabs; a tab outside folders, the divider, and the New Tab row place it last at the top of its list.
  - A folder's row takes the dragged folder even when it is the folder's parent, which puts it last there; otherwise the end of a parent's folders could not be reached by dragging when the parent holds no tabs. When it is already last there, the row does not light up, since the drop would change nothing. Move to Folder still leaves the parent out.
  - A dragged folder stays in its list, as Move to Folder keeps it: moving it between the pinned and open lists would pin or unpin every tab inside it and give or clear their saved pages.
  - Places that a collapsed folder would hide are refused, so the slot stays in view; a collapsed folder's own row still takes the folder.
  - A drop on another space's symbol, or Move to Space, puts the folder at the top of that space's list of its kind and keeps the folders inside it and their parents. The tree does not know Personas, so the session checks the space (`canMoveFolder(_:toSpace:)`): into another Persona's space the folders take new IDs and each tab inside is replaced by a new tab of that Persona (`docs/windows-personas.md`, Moving tabs between spaces). The tabs inside leave the split view of the space they leave, and a window that selects one of them follows it, as for a dropped tab.
  - The release that ends a drag does not collapse or expand the folder: the row's click is ignored while the drag state holds an item, as a favorite tile's is.

## Bookmarks menu (III.20, built)

- The menu sits between Spaces and History and is built each time it opens (`menuWillOpen(_:)`), as the History menu's pages are, from `BookmarkMenu.entries(for:personas:spaces:favorites:tree:)`, a value tree without AppKit.
- Contents, for the sidebar target (window rule 7): the window's Persona's favorites in their grid order, each named by its title, headed by the Persona's name with two or more Personas; then, for each Persona in order, each of its spaces that has pinned tabs as a submenu, titled with the space's name, or "Persona / Space" with two or more Personas. A space's submenu holds its pinned folders as nested submenus, each listing its folders before its tabs, as the sidebar does, then its pinned tabs outside folders. Without bookmarks the menu shows a disabled No Bookmarks.
- Choosing a tab selects it in the sidebar target as a sidebar click does (window rule 2); choosing a favorite acts like a click on its tile.
- Decisions made while building it:
  - The menu is filled in `menuWillOpen(_:)` rather than `menuNeedsUpdate(_:)`, which AppKit also calls to search the menu for each key equivalent the user presses, so a key press does not walk every tab. Until it first opens, the menu holds only No Bookmarks, so Settings ▸ Shortcuts, which lists the menu bar at launch, lists none of its items, and its items have no shortcuts.
  - A divider separates the favorites from the spaces and each Persona's spaces from the next Persona's, as the bottom bar sets each Persona's symbols apart.
  - A folder or space whose pinned list holds no tab at any depth is left out, since it offers nothing to choose. Collapsed folders list what they hold, since collapsing belongs to the sidebar's rows. A folder's submenu offers no item of its own, since nothing opens a folder as a whole.
  - A tab is named as its row names it (`Tab.shownTitle`: the user's name, a hook's name, or the page's title, with a web extension's name for its page without a title), and a favorite by its title, or by its host when it has none, as the History menu's pages are; each item's tooltip is its address. Items show no site icons, as the History menu's pages show none.
  - While no main window is open, the menu lists the favorites of the Persona that the window to reopen shows (`BrowserSession.sidebarTargetPersonaID`), read without opening the window; choosing an entry opens it.
  - Choosing an entry brings the sidebar target forward, out of the Dock when it is minimized, also from behind Settings or a small window, as History's Open does, because the user chose a page to see. A tab or favorite that went away while the menu showed, and a favorite of a Persona other than the window's, select nothing.
  - Code: `BookmarkMenu.swift` holds `BookmarkMenu.Entry`, `BookmarkMenu.Choice`, `entries(for:personas:spaces:favorites:tree:)`, which tests call with `PageStub` tabs, and the session's `bookmarkMenuEntries` and `openBookmark(_:)`; `sidebarTargetPersonaID` is in `BrowserSession.swift`, beside `sidebarTarget()`, since it reads the windows to reopen. `AppDelegate` turns the entries into menu items (`fillBookmarks(_:with:)`) and passes the chosen item's `Choice` to the session.

## session.json

- III.16 (version 14, built): `TabRecord.savedPage`. `normalized()` gives a pinned record without one, open or closed, its address and title, when it has an address, and drops it from an unpinned record. `TabRecord.closed` keeps it, so a reopened pinned tab returns with its saved page. A closed record needs the repair as much as an open one: a WebKit page reports the address it opens at before its tab exists, so a reopened pinned tab without a saved page would save the next address it reports instead.
- III.18 (version 15, built): `TabFolder.parentID`. `normalized()` clears a parent that is missing, in another space or list, or the folder itself; in each cycle, the parent of the cycle's first folder in the file; and the parent of a folder at the fifth level, which rises to the top of its list with what it holds, until every folder is within the fourth level (`FolderTree.repairingParents(of:)`). A file before version 15 loads its folders at the top level. Agent folders are never encoded (VII.12).
- III.22 (version 16): `TabFolder.live` and `TabRecord.liveItemID` kept live folders and their item tabs. Since their removal a version 16 file's live folder loads as an ordinary folder without its item tabs, and the file stays at version 16 (Live sources).
- Older builds ignore these fields. When they save, saved pages and parents are dropped. The next load gives pinned tabs their current pages as saved pages again, and the folders become one level deep.

## Interactions with other features

- Sync (V.9): a pinned tab syncs its saved page, the user's name, engine, order, space, and folder, not its current address, which settles open decision 2 of `docs/sync.md`. Folders sync their name, parent, and order. Every tab's current page stays on each Mac.
- Browser import (V.12, built): each imported pinned tab's saved page is its imported address, and an address counts as already pinned in a space when one of its pinned tabs has it as its saved page, wherever that tab's page went (III.16, built). Folders stay one level deep (bookmark rule 6).
- Agents: A folder is ordinary or an agent folder, never both. Each agent folder stays at the top level of the open list and takes neither nested folders nor incoming tabs. Its tabs remain loaded while the agent owns them. Closing an unkept agent tab or deleting its Persona forgets the tab and leaves no undo entry. Moving its last tab out removes the empty folder. Keep Tabs makes the folder and its tabs ordinary sidebar items.
- Web extensions: a tab without its page is left out of the windows the host reports, as a restored tab is today, so unloading a tab removes it from the extensions' view until it loads again. An extension's `tabs.remove` goes through `TabCloseAction`, so it unloads a pinned tab (Unloading).
- AI hooks: unloading posts nothing.
- The palette and the tab switcher list tabs without pages, as they list restored tabs, so the palette finds unloaded pinned tabs by title.
- History: a pinned tab records a visit when the user opens its page.
- Split view: closing a pane's tab takes it out of the split view. Automatic unloading keeps the pane and loads its page again when shown.
- Small windows: a small window's tab is never pinned, so none of this applies there.
