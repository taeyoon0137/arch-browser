# Bookmarks and live folders design

## Purpose and scope

- This note designs rows 64 (bookmarks) and 65 (live folders) of `docs/features.md` and queue tasks III.16 to III.25 in `docs/plan.md`. Every label it adds follows Persona rule 7 of `docs/windows-personas.md`: a Persona named with one of its spaces shows as "Persona / Space", as the space header, the window title, and the bottom bar's tooltips already show it.
- Bookmarks: pinned tabs, favorites, and the folders that hold pinned tabs become Arch's bookmarks. Each keeps a saved page to return to and can unload and reload its page. Folders nest, and a Bookmarks menu lists them.
- Live folders: pinned folders filled and kept up to date by a source: RSS and Atom feeds fetched directly, and GitHub pull requests, review requests, and issues through the user's `gh` command-line tool signed in through the built-in terminal. Each item is a tab with read and unread state.
- Excluded: a bookmarks bar, because nothing sits above the page (Approach in `docs/plan.md`); a bookmark manager window, because the sidebar, the Bookmarks menu, and the palette, which already lists pinned tabs, cover it; live sources that need a service's own sign-in and API, such as calendars, documents, and chats (open decision 1); custom icons for folders and tabs; and muting, which Arch's tabs do not have.
- Arch runs no server and no service of its own for any of this. Nothing here uses a private API or needs a flag on `flags://`.

## Facts this design relies on

### Arch today

- A pinned tab is a tab with `isPinned` and, since III.16, a saved page (`Tab.savedPage`), which `session.json` keeps beside its current address and title. Closing it unloads it to its saved page (Unloading, III.17); Delete Tab moves it to the closed list, whose record keeps the saved page.
- A favorite's `url` and `title` already act as its saved page: Close ends the favorite's tab, and the next click opens the favorite's address. `savedFavoriteTabs` keeps the last session's tabs as records (address, engine, page state) until their favorites are clicked.
- A restored tab has an `UnloadedWebContents` stand-in until a window first shows it (III.14), and so does a tab whose page unloaded (Unloading, III.17) until a window next shows it. A load on the stand-in replaces its saved page without loading.
- A tab's page state is its engine's `restorableState`: on WebKit, `interactionState`, which brings back the back list and the scroll position. The Chromium adapter keeps none (`restorableState` is nil), so a restored Chromium tab loads its last address without its back list (regression check 58).
- Leaving a page: Chromium's `tryToClose` runs the page's `beforeunload` handlers, which ask through `runBeforeUnloadPanel`. WebKit's agrees at once, because WebKit has no public way to run them. Neither engine tells the app whether a page holds unsaved input; both run page scripts in every frame (`EnginePageScript`).
- `EngineWebContents.isCapturingMedia` follows WebKit's public `cameraCaptureState` and `microphoneCaptureState` on `WKWebView` (macOS 12), which have no counterpart for screen sharing, and CEF's `CefDisplayHandler::OnMediaAccessChange(browser, has_video_access, has_audio_access)` (III.17).
- Remembered permissions (`permissions.json`) keep Allow and Don't Allow per origin and type, notifications among them. A Chromium page's notifications come from the page (row 40), so they stop while its tab has no page.
- `BrowserSession.closeTab(_:reason:)` closes a tab as `TabCloseAction` decides for its kind and the reason (III.17, Unloading). Its callers: `requestCloseTab` once the page agrees (⌘W, the row's button, Close Tab, Close Other Tabs, which skips pinned tabs, and a small window's close); `tab.didClose`, when the page closes itself or the engine closes its crashed page; `SessionWebExtensionHost.close`, for an extension's `tabs.remove`; `didOpenOnlyDownload` and the start of the download it waits for, for a tab that only pointed at a file, which a restored tab (`isRestored`) reaches without fetching the file; `deletePersona`, which closes each of the Persona's tabs without asking; and archiving, which closes only unpinned tabs. `requestDeleteTab` closes a pinned tab into the closed list. The closed list keeps 100 records.
- Folders nest up to four levels in a space's pinned or open list (Nested folders, III.18). Browser import joins nested folder names into one level ("Work / Docs"). Folder rows drag among the rows, into other folders, and to another space's symbol (III.19).
- `Tab.isUnread` puts a dot on the row of a tab that a page opened in the background; selecting the tab clears it. It is not saved.
- `session.json` is at version 16: the session fixes took version 13 to seal page state (`SessionStateSeal`), III.16 version 14 for saved pages, III.18 version 15 for folder parents, and III.22 version 16 for live folders. Each step that adds fields takes the next free version number when it lands and migrates through `normalized()`. VII.12 adds `TabFolder.agentSessionID`, which is not encoded, for agent folders among the open tabs.
- `AI` runs command-line tools through `CommandLineProcess` (`posix_spawn`, its own process group, pipes, a minimal environment) and finds them with `LoginShell.locateExecutable(named:)` in the login shell's PATH. Since III.21 both are public, and `LoginShell.variables()` reads `GH_CONFIG_DIR` and `XDG_CONFIG_HOME` through `printenv`, so only exported values count, with PATH in one login shell run, once per launch and again after `LoginShell.reload()` (Check Again), which only `GitHubCLI` passes on; `baseEnvironment` holds `HOME`, `USER`, `LOGNAME`, `SHELL`, `PATH`, `LANG`, `TMPDIR`, and `TERM=dumb`; a command-line provider adds the non-secret variables of its configuration (`docs/ai.md`). Settings opens the built-in terminal through a closure the app shell sets (`PreferencesWindowController.openTerminal`).
- `FaviconLoader` caches icons by icon address, shares concurrent downloads, and clears its cache once it holds 200. At every launch `restoreTabs` has each restored tab's stand-in request its site's `/favicon.ico` (`loadSiteIcon()`), and a load on a stand-in requests the new site's.
- The app's Info.plist sets no App Transport Security exception, so the app's own `URLSession` refuses plain HTTP, as for site icons.
- Browser import counts an address as already pinned in a space by each pinned tab's current address (`tab.url`) and, since III.16, its saved page, and merges an imported folder into a pinned folder of the same name (`SidebarImport`).
- The bottom bar lists every Persona's spaces, and each symbol's tooltip and accessibility label is `BrowserSession.displayedPlace(ofPersona:space:)`, "Persona / Space" with two or more Personas, or the space's name alone with one (`SidebarBottomBar`). New Persona gives every new Persona a space named Personal.

### Feeds

- RSS 2.0: `rss/channel/item` with `title`, `link`, `guid` (`isPermaLink`), and `pubDate` (RFC 822); `channel/ttl` is minutes between fetches. RSS 1.0: `rdf:RDF/item` with `rdf:about`, `title`, `link`, and `dc:date` (ISO 8601); the syndication module's `sy:updatePeriod` and `sy:updateFrequency` set an interval. Atom 1.0: `feed/entry` with `id`, `title` (`type` text, html, or xhtml), `link` (`rel="alternate"` or no `rel`), `updated`, and `published`.
- Foundation's `XMLParser` reads all three; it resolves no external entities unless asked.
- A server that sends `ETag` or `Last-Modified` answers `If-None-Match` or `If-Modified-Since` with 304 when the feed has not changed.
- A web page names its feeds in `<link rel="alternate" type="application/rss+xml">` or `type="application/atom+xml"` with an `href`.

### GitHub CLI

Checked on this Mac with `gh` 2.104.0, in an environment with only `HOME`, `USER`, `LOGNAME`, `SHELL`, `PATH`, `LANG`, `TMPDIR`, `TERM=dumb`, `GH_PROMPT_DISABLED`, `GH_NO_UPDATE_NOTIFIER`, and `NO_COLOR`:

- `gh api graphql --hostname github.com --input -` sends the JSON body `{"query": …, "variables": {…}}` from standard input and prints the response. `gh` read its sign-in from the Keychain itself and asked nothing.
- GitHub's search through GraphQL (`search(query: $q, type: ISSUE, first: $n)`) accepts `@me`, `archived:false`, and `sort:updated-desc`: `is:pr is:open author:@me`, `is:pr is:open user-review-requested:@me`, `is:pr is:open involves:@me`, and `is:issue is:open assignee:@me` all answered. An unknown qualifier is searched as text and gives no error.
- Pull request nodes gave `number`, `title`, `url`, `updatedAt`, `state` (`OPEN`), `isDraft`, `reviewDecision` (null and `REVIEW_REQUIRED` seen), `mergeable` (`UNKNOWN`, `MERGEABLE`, and `CONFLICTING` seen), `repository.nameWithOwner`, `author.login`, and `commits(last: 1).nodes[0].commit.statusCheckRollup.state` (`SUCCESS`, `FAILURE`, or null). Issue nodes gave the same fields without the pull request ones. `rateLimit { cost remaining resetAt }` reported a cost of 1 per query.
- Signed out (an empty `GH_CONFIG_DIR`), `gh auth status --hostname github.com` exits 1 and `gh api` exits 4. Signed in, `gh auth status` exits 0. A malformed GraphQL query exits 1.

## Decisions

Code comments and documents cite these rules by number, as in "bookmark rule 4".

### Bookmark rules

1. Pinned tabs, favorites, and the folders that hold pinned tabs are the bookmarks. Arch keeps no separate bookmark store, bar, or manager. Import, sync, and the palette already treat them as bookmarks; one place to organize them is enough.
2. Each pinned tab keeps a saved page: an address and a title. A tab saves the page it shows when pinned (Pin Tab, a drop among the pinned tabs or into a pinned folder), or the first address its page reports if it had none. Unpinning clears the saved page. A reopened pinned tab keeps the saved page from its record. Browser import gives an imported pinned tab its address, and a live folder gives each item's tab the item's address and title. Use Current Page as Saved Page and Edit Saved Address… change it. A favorite's address and title are its saved page.
3. A tab is on its saved page while its address equals the saved one, ignoring the fragment, `http` against `https`, the host's case, a leading `www.`, and a trailing slash. It is on its saved site while its host equals the saved host the same way. Go Back to Saved Page is offered whenever a pinned tab or a favorite's tab is off its saved page; the row offers it only while the tab is off its saved site. A pinned web app changes its address constantly, and redirects and returns from sign-in pages would otherwise mark the row.
4. Closing a pinned tab unloads it: once its page agrees to leave, the page closes and the tab keeps its place with a stand-in at its saved page, without page state. This applies to ⌘W, the row's button, Close Tab, an extension's `tabs.remove`, and the page's `window.close()`; Unloading lists every path that closes a tab. Unloading adds nothing to the closed list or the tab close log, and, as when a favorite's tab ends, ⌘Z then reopens none of the tabs closed before it. Delete Tab removes a pinned tab into the closed list. A favorite's Close ends its tab, as today. Closing a live folder's item tab dismisses the item (live folder rule 4). A bookmark outlasts its page, and returning to it starts at the saved page.
5. Pinned tabs and favorites' tabs that no window shows unload automatically and keep their place. The stand-in keeps the address, title, icon, and the engine's page state: a WebKit tab comes back where it was, with its back list; a Chromium tab, whose adapter keeps no page state, loads its last address without its back list, as after a relaunch (open decision 5). The archive timer unloads those inactive for the hours set in Settings ▸ Sidebar (Unload Pinned Tabs and Favorites After, 12 hours by default, 0 for never). While that setting is not 0, memory pressure reported by macOS (`DispatchSource.makeMemoryPressureSource`) also unloads every tab that no window shows, open tabs included: at a warning those inactive for 30 minutes, at critical all of them. A tab stays loaded while it plays sound or media, shows a video in picture in picture, also paused or muted, since the system's window closes with the page, uses the camera, microphone, or screen, holds text the user typed since its page loaded, shows a site allowed to post notifications, has a prompt waiting, has downloads that need its page, is in a small window, opened a page that a window shows, as a sign-in popup that reports back to it, or sits in an agent folder (VII.12). Sound counts only from audio and video elements in the page's documents, which both engines' media scripts watch; Web Audio and an element outside the document, as many games and some players use, keep no tab loaded (risk 8). A call, a page the user is writing in, and a web app that posts notifications must not stop because the user looked elsewhere. An automatic unload answers a Chromium page's `beforeunload` question with Stay, without a card, which keeps the page. WebKit cannot run those handlers, so on WebKit the typed text exclusion keeps drafts, as it does on Chromium pages without a handler.
6. Folders nest up to four levels in the pinned and open lists. A folder lists its folders first, then its tabs, as each list does. Live folders and agent folders hold no folders. Bookmark collections nest, and four levels at 12 points each leave the 240-point sidebar room for names. Browser import keeps joining nested names into one level, as `docs/import-browsers.md` describes: its record finds a folder by the source folder's ID, but merging by name, used when the record finds none, compares the joined name, which keeps source folders of the same name in different places apart.
7. The Bookmarks menu in the menu bar lists the window's Persona's favorites and every space's pinned folders and tabs, one submenu per space. With two or more Personas, the spaces group by Persona and each submenu is titled "Persona / Space", while the favorites, which belong to the whole Persona, are headed by the Persona's name alone (Persona rule 7).

### Live folder rules

1. A live folder is a pinned folder that a source fills and keeps up to date. Its source, item limit, and refresh interval belong to the folder in `session.json` (`TabFolder.live`) and can sync with it, apart from a private feed's address (rule 8). The fetched items, read state, dismissed items, and fetch state belong to `live-folders.json`, since they change with every fetch and stay on each Mac. A live folder sits among a space's pinned tabs, at the top level or in an ordinary folder, and holds only its items.
2. Sources: an RSS (2.0 or 1.0) or Atom feed over HTTPS, and GitHub searches that the user's `gh` runs: My Pull Requests, Review Requests, Assigned Issues, or a search the user writes. A feed travels from its site to Arch, and GitHub's answers from GitHub through `gh` to Arch; no server of Arch's own takes part. An `http` feed address is tried as `https`, because the app's `URLSession` refuses plain HTTP.
3. `gh` keeps its own sign-in. The user installs it and signs in with `gh auth login` in the built-in terminal (row 56), as for the AI module's command-line tools. Arch finds it through the login shell's PATH, runs only `gh auth status` and `gh api graphql` with a fixed query, sends the search on standard input, and never runs `gh auth token` or reads gh's files or Keychain items.
4. Each item is a pinned tab in its folder, whose saved page is the item's address and title (bookmark rule 2); it has no page until a window shows it. Closing an item's tab dismisses the item: the tab is removed without joining the closed list, and the item stays out of the folder while the source lists it, until Show Dismissed Items. A tab moved out of its live folder becomes an ordinary tab, pinned with the item's saved page, or open without one after Unpin Tab or a drop among the open tabs (bookmark rule 2), and the folder immediately gets a new tab for the item. Nothing else enters a live folder, and its tabs keep the source's order.
5. An item is unread when it appears after the folder's first fetch, or, for GitHub, when its `updatedAt` is later than the last time a window showed its tab or stopped showing it. A dot marks an unread item's row, and the folder's row shows how many are unread. A window showing the tab marks it read; Mark as Read, Mark as Unread, and Mark All as Read change it manually.
6. A folder refreshes when it is created, on Refresh Now, and when its interval has passed since its last attempt: 15 minutes, 30 minutes, 1 hour, or 3 hours, by default 30 minutes for feeds and 15 for GitHub, checked every 5 minutes through `NSBackgroundActivityScheduler`. A GitHub folder also refreshes when Arch becomes active or a window shows its space, at most once every 5 minutes, since pull requests change while the user works. A feed's `ttl` or syndication interval lengthens its interval, up to 24 hours. After a failure, the wait doubles, up to 6 hours; a failure while the Mac is offline does not count. `Retry-After` and GitHub's rate limit reset postpone the next attempt, and Low Power Mode doubles every interval. At most four fetches and one `gh` process run at once.
7. Limits: 10, 25 (default), or 50 items per folder; 20 live folders in the app; 5 MB per feed response; 8 MB of `gh` output; 30 seconds per fetch; titles cut at 300 characters; item addresses only `http` and `https`; feed addresses without a user name or password, since feeds load without credentials (a token in the query is kept as rule 8 says).
8. A feed address with a query can carry a token, as private feeds do (`?token=…`), so Arch keeps such an address only in a Keychain item. `session.json` keeps the address without its query and fragment, marked as kept in the Keychain, and the folder stays on its Mac, since Keychain items never sync (`docs/sync.md`). Errors and tooltips show the address without its query. Arch cannot tell a token in an address's path from the rest of the path, so such an address is kept and synced as any other (risk 7).

## Saved pages (III.16, built)

- `SavedPage` holds an address and a title. `Tab.savedPage` follows bookmark rule 2: `isPinned` turning on sets it from the tab's address and page title, turning off clears it, and a pinned tab without one takes the first address its page reports, with an empty title. `restore(_:folderID:)` takes the saved page from the record, and `takeImport(_:)` from the imported address and title.
- `URL.isSamePage(as:)` and `URL.isSameSite(as:)` compare according to bookmark rule 3. `Tab.isOffSavedPage` and `Tab.isOffSavedSite` use them; a favorite's tab compares with its favorite's address, which the session supplies.
- Go Back to Saved Page loads the saved address in the tab, or the favorite's address in its tab. For a tab without its page, the stand-in takes the saved page without loading, as any load on it does.
- Use Current Page as Saved Page takes the tab's address and page title. For a favorite it changes the favorite's address and title; it is disabled while another favorite of the Persona has that address.
- Edit Saved Address… opens an `NSAlert` sheet on the window, as New Persona does, with a text field prefilled with the saved address. An address that `BrowserSession.url(forInput:)` rejects changes nothing. A tab without its page moves its stand-in to the new address. For a favorite, Edit Favorite… has Name and Address fields.
- Copy Address copies the tab's current address, or the favorite's, as a URL and as text. Duplicate opens and selects a copy after the tab, in the same list and folder, at its current address in its engine; a pinned copy keeps the original's saved page.
- Where: the tab row's context menu (Go Back to Saved Page, Use Current Page as Saved Page, Edit Saved Address…, Copy Address, Duplicate), the favorite tile's (Go Back to Saved Page, Use Current Page as Saved Page, Edit Favorite…, Copy Address), and the Tab menu (Go Back to Saved Page, Use Current Page as Saved Page, Edit Saved Address…, acting on the selected tab). They have no default shortcuts; Settings ▸ Shortcuts can assign one. Item tabs offer Go Back to Saved Page and Copy Address only, since the source owns their address.
- While a tab is off its saved site, its row shows a back button (`arrow.uturn.backward`) before the close button when under the pointer, with a tooltip naming the saved address.
- Decisions made while building it:
  - A saved page's title is the page's title as the tab reports it, which is empty for a page that has shown none yet, as for a tab pinned before its page reported an address. A saved page taken from the first address a page reports starts with an empty title, since the tab's title is still the previous page's then. An empty saved title takes the first title the page shows at the saved address.
  - Edit Saved Address… keeps the saved title while the new address names the same page and leaves it empty otherwise, so the page's own title fills it once the tab shows it there. Text that `url(forInput:)` rejects beeps. Edit Favorite… keeps the name when its field is left empty, and refuses, with a beep, an address that another favorite of the Persona has, as Use Current Page as Saved Page does, since a Persona's favorites come once per address (`addFavorite(_:)`).
  - The favorite commands act on the favorite's open tab. A tab saved for the favorite from the last session, which has no page until the favorite's first click, counts once that click opens it. The tile's Go Back to Saved Page and Use Current Page as Saved Page come from a view that observes the tab (`FavoriteTabSavedPageItems`), because the grid redraws only with the window's selected tab and the session's lists, so a page change in the tab while another tab is selected would otherwise leave the menu as it was.
  - A tile drops an icon that arrives after its favorite moved to another site, so the old site's icon cannot replace the new one.
  - The context menus show Go Back to Saved Page only while it applies; the Tab menu keeps it and disables it otherwise, and also while an internal page or the preview panel covers the tab, as Home does. The Tab menu's Edit Saved Address… is for pinned tabs only; a favorite's tile has Edit Favorite….
  - Duplicate does not copy the user's name for the tab, and the window whose row it came from selects the copy.
  - A tab row's menu keeps the Page Address plugin's own Copy Address in that plugin's section, which can copy a Markdown link; the row's Copy Address copies the address alone and does not depend on the plugin.
  - Code: `SavedPage.swift` holds `SavedPage`, the comparisons, the tab's saved page methods (`isOffSavedPage`, `isOffSavedSite`, `goBack(toSavedPage:)`, `useCurrentPageAsSavedPage()`, `setSavedAddress(fromInput:)`), the favorite's (`Favorite.usingCurrentPage(of:among:)` and `edited(name:address:among:)`, which give the changed favorite or nil), and the session's saved page commands; `BrowserSession.duplicateTab(_:)` and `updateFavorite(_:_:)`, which change the session's lists, live in `BrowserSession.swift`. Browser import gives an imported pinned tab its saved page through `Tab.takeImport(_:)` and reads each space's tab through `SidebarImport.Sidebar.TabState.init?(_:)`, so tests check both on `PageStub` tabs. `Tab.isPinned` saves and forgets the saved page as it changes, so every way of pinning and unpinning follows bookmark rule 2.

## Unloading (III.17, built)

- Closing a pinned tab (bookmark rule 4) asks the page as closing does, then follows the closing steps without removing the tab: a window that shows its page in full screen leaves it, its prompts end, it leaves its split view, each window that selected it selects another tab as after a close (window rule 3, `BrowserSession.tabToSelect(after:opener:splitNeighbor:among:spaceID:isShownInAnotherWindow:)`), and `retire` closes the page, keeping it on a blank page while its downloads need it. The tab then holds `UnloadedWebContents(url:title:engine:state:)` at its saved page, or at its address without one, without state, which requests the site's icon. Its first load at the saved page counts as a visit.
- `TabCloseAction.of(_:reason:)` decides what a close does: unload for a pinned tab, end for a favorite's tab, dismiss for a live folder item's tab (live folder rule 4), and close for any other tab, into the closed list unless it only pointed at a file. Forget for an unkept agent tab (close without the closed list or the tab close log, `docs/agents.md` decision 10) joins with VII.12. Every path that closes a tab goes through `BrowserSession.closeTab(_:reason:)`, or through `requestCloseTab(_:)`, which asks the page first (`whenPageAgreesToLeave`): while the tab's leave-page card shows, that card is the question and the tab only comes forward, and otherwise the tab's prompts end before the page is asked (`TabPromptQueue.endForClose`):
  - ⌘W, the row's button, Close Tab, Close Other Tabs, and a small window's close (`requestCloseTab`), the page's `window.close()` and a crashed page that the engine closes (`tab.didClose`), and an extension's `tabs.remove` (`SessionWebExtensionHost.close`): the action for the tab's kind, so an extension unloads a pinned tab.
  - A tab that only pointed at a file (`didOpenOnlyDownload`, and the download's start): a pinned tab unloads to its saved page and keeps its place; a favorite's tab ends; any other tab closes without the closed list. Unloading clears `isRestored`, so opening the tab again downloads the file. An item tab unloads the same way, so the next plan does not remove its tab and add it again, and so does an item tab whose crashed page the engine closes, since the user did not choose to dismiss the item.
  - Delete Persona (`deletePersona`, reason `persona` in the tab close log): the Persona's pinned and open tabs close into the closed list without asking, and its favorites' tabs end. Its item tabs close without the closed list, so the up to 1,000 item tabs of 20 live folders cannot push other records out of its 100; agent tabs follow with VII.12.
  - Archiving closes only unpinned tabs, so it reaches no pinned or item tab.
- ⌘Z reopens only a tab that joined the closed list. After an unload or a favorite's end, ⌘Z reopens none of the tabs closed before it, rather than an older tab in its place. A close whose page agreed only after the tab had closed another way does nothing and counts for neither (`closeTab` returns whether the tab was still open).
- Delete Tab, in a pinned tab's context menu, asks the page, then closes the tab into the closed list (`requestDeleteTab(_:)`); ⌘Z reopens it pinned in its folder with its saved page.
- Automatic unloading (bookmark rule 5): `TabUnloading.tabsToUnload(_:now:after:pressure:)` picks from `UnloadCandidate` values (ID, kind, last activation, and exclusions) without session state, so tests drive it directly. Every 30 minutes the archive timer calls it, after archiving, with the hours that Settings ▸ Sidebar saves under `ARCHUnloadAfterHours` (12 by default, 0 for never); `MemoryPressureMonitor`, a `DispatchSource.makeMemoryPressureSource` on the main queue, calls it with the event's level. Candidates are loaded tabs that no window shows. A tab's last activation is when a window last selected it or stopped showing it, or the archive timer last found it shown.
- An automatically unloaded tab, pinned, open, or a favorite's, keeps its place, folder, split view, and ID, and a favorite's tab stays its favorite's, whose tile then dims without its dot, as a favorite without an open tab does, until a window shows the tab again (`BrowserSession.hasOpenPage(_:)`). Its stand-in keeps its address, title, icon, and its engine's page state (`Tab.unloadKeepingPage()`), which a Chromium page lacks; the page takes its host's remembered zoom again once it loads. Nothing joins the closed list or the tab close log, and a window loads the page again as it shows the tab, each pane as it shows a split view.
- The exclusions of bookmark rule 5 (`UnloadExclusion`) come from:
  - Capture: `EngineWebContents.isCapturingMedia`, which `webContentsDidChangeMediaCapture` on the UI delegate reports (`docs/engine-protocol.md`). The WebKit adapter observes `cameraCaptureState` and `microphoneCaptureState`, counting active and muted; the Chromium adapter takes CEF's `OnMediaAccessChange` through the bridge's `cefBrowserDidChangeMediaAccess(video:audio:)`; the stand-in reports false.
  - Typed text: `TabUnloading.inputScript`, a page script in a world of Arch's own (`arch.unloading`) that runs first in every frame's document at document start, sends `start` from each new main frame document, again from a main frame back from the back-forward cache, and `typed` at the first `input` event the user causes (`isTrusted`) in a document. `Tab.hasTypedInput` turns on with `typed` and off with the main frame's `start` and with another web contents. On Chromium the page shares the script's world, so a page could at most keep its own page loaded.
  - Notifications: the session's remembered permissions, for the origin of the tab's address.
  - Picture in picture: `EngineWebContents.isInPictureInPicture`, which also keeps a paused video and one muted from the start, which the sound exclusion misses, so the system's window stays open. The Chromium adapter reports it from the engine's start of picture in picture until AVKit has finished stopping (`ChromiumPictureInPicture`). WebKit's media script reports each document's `document.pictureInPictureElement` and its videos' `webkitPresentationMode` at its media events and at `enterpictureinpicture`, `leavepictureinpicture`, and `webkitpresentationmodechanged`, so a video inside a shadow root counts only through `pictureInPictureElement`; the stand-in reports false.
  - Sound and media (`isAudible` and the media session's playback state, which the media scripts learn from the document's `video` and `audio` elements, so Web Audio and elements outside the document go unseen), a prompt that waits or shows as a card (`TabPromptQueue.hasPrompt(for:)`), downloads (`closingStopsDownloads`, or a file the tab waits to download), a small window, open developer tools, which unloading would close, and an opener: a tab whose page opened one that a window shows (`Tab.opener`), so a sign-in popup's `window.opener` stays alive and its `window.close()` returns to the tab. Agent folders join with VII.12.
- The automatic path sets `Tab.answersBeforeUnloadWithStay` for its call to `tryToClose`, so a Chromium page's leave-page question returns Stay without a card and the page stays loaded until the next try. A close the user asks for meanwhile clears it, so the page's question shows for that close, and the page's answer reaches only that close. WebKit's `tryToClose` agrees at once, so on WebKit the typed text exclusion is what keeps a draft.
- Rows of tabs without a page show their icon and title dimmed (`SidebarDimming.unopened`), as rows of tabs restored from the last session do, so the sidebar shows which tabs have pages; a selected row, whose tab a window loads, is not dimmed. A pinned row's close button, under the pointer, is a minus (`minus`) with the tooltip Unload, shown only while the tab has its page. ## Live folders

### Sources

- `LiveFolderSource` is a feed address or a `GitHubSearch`: a host (`github.com` or a GitHub Enterprise Server host) and a kind with its search:
  - My Pull Requests: `is:pr is:open author:@me archived:false sort:updated-desc`.
  - Review Requests: `is:pr is:open user-review-requested:@me archived:false sort:updated-desc`. Requests to the user's teams need a search of their own with `review-requested:@me`.
  - Assigned Issues: `is:issue is:open assignee:@me archived:false sort:updated-desc`.
  - Search: the user's text in GitHub's search syntax, with ` sort:updated-desc` added when it has no `sort:`.
- `LiveFolderConfiguration` holds the source, the item limit, and the refresh interval. `TabFolder.live` keeps it, with a private feed's address reduced as live folder rule 8 says.
- `LiveFolderKeychain` keeps private feed addresses: one generic password item per folder, service `xyz.taeyoon.arch.live-folders`, account the folder's ID, label `Arch Live Folder: <folder name>`, which a rename by Rename Folder or Edit Live Folder… changes without reading the address (`LiveFolderService.setPrivateAddressFolderName(_:for:)`), accessible when unlocked, not synchronizable, read once per launch at the folder's first refresh and kept in memory, as `AIKeychain` does. Tests use an in-memory store.

### Feeds

- `FeedFetcher` loads the feed through a `URLSession` with an ephemeral configuration, no cookies, no cache, a 30-second limit, and an `Accept` header for RSS, Atom, and XML. Its requests carry the stored validators. A 304 keeps the items. 429 and 503 with `Retry-After`, in seconds or as a date, postpone the next attempt. Another status is an error that names it. The body stops at 5 MB. A redirect is followed only to another `https` address without a user name or password. `FeedFetcher.discover(_:)` loads an address for the sheet and answers the feed it is or the feeds its page names (`FeedDiscovery.Outcome`).
- Feeds load outside every Persona's engine storage, so no site sees the user's sign-ins or cookies, and a feed that needs a signed-in session cannot load. A private feed whose address carries a token in its query works; the address stays in the Keychain (live folder rule 8).
- `FeedParser` parses with `XMLParser`, namespaces on and external entities off, and recognizes the format by its root element (`rss`, `rdf:RDF`, or `feed`); anything else is not a feed. For each item:
  - ID: Atom `id`, RSS `guid`, RSS 1.0 `rdf:about`, else the item's address. Items without an address are skipped, so every kept item has an ID.
  - Address: Atom's alternate link, the RSS link, or a `guid` that is a permalink, resolved against `xml:base` and the feed's address. Items without an `http` or `https` address are skipped.
  - Title: plain text with markup removed and character references decoded (numeric ones and the common named ones), whitespace collapsed, and cut at 300 characters; an Atom title of type `text` is plain already and only has its whitespace collapsed. Without one, the address without its scheme.
  - Date: Atom `updated`, else `published`; RSS `pubDate` in RFC 822 forms with or without the weekday and with numeric or named zones; `dc:date` in ISO 8601 with or without fractions.
- Items keep document order, or newest first when every item has a date; of two items with one ID, the first counts. The first items up to the folder's limit are kept. The feed's title becomes the folder's default name.
- `FeedDiscovery` reads an HTML page's first 512 KB for `<link rel="alternate">` tags of the RSS and Atom types and returns up to ten addresses resolved against the page, with their titles.

### GitHub

- `GitHubCLI.locate()` finds `gh` with `LoginShell.locateExecutable(named: "gh")` once per launch and again on Check Again or when the file is gone. Check Again (`locate(again: true)`) also reads the login shell again (`LoginShell.reload()`), so a PATH or `GH_CONFIG_DIR` that a profile gained in the built-in terminal, as when the user installs a package manager there, counts without a relaunch.
- `GitHubCLI.status(host:)` runs `gh auth status --hostname <host>`: exit 0 is signed in, any other exit is signed out, and a missing executable is not installed.
- `GitHubCLI.search(_:limit:)` runs `gh api graphql --hostname <host> --input -` with the fixed query below on standard input and the search and limit as variables, through `CommandLineProcess` in a new empty folder under `TMPDIR`, with the minimal environment of `LoginShell.baseEnvironment` plus `GH_PROMPT_DISABLED=1`, `GH_NO_UPDATE_NOTIFIER=1`, and `NO_COLOR=1`, and `GH_CONFIG_DIR` and `XDG_CONFIG_HOME` when the login shell sets them to absolute paths, so that `gh` finds the sign-in that `gh auth login` wrote from the built-in terminal. `LoginShell` prints those two after PATH in the same login shell run (`LoginShell.variables()`, once per launch and again after Check Again's `LoginShell.reload()`), through `printenv`, so only exported values count and a profile with `set -u` or `setopt nounset` still prints every line. No other variable of the shell reaches `gh`, so token variables such as `GH_TOKEN` and `GITHUB_TOKEN` never do. `GitHubCLI.status(host:)` runs with the same environment. It ends the process after 30 seconds or 8 MB of output. Exit 4 means signed out. Exit 1 shows the first GraphQL error's message, or the last line of standard error, cut at 200 characters, unless every error's `path` points at one result in `search.nodes`, as for a result in an organization whose SAML enforcement the sign-in was not granted for, which GitHub answers as null: the other results are then the folder's items, and the read state and dismissals of the items they leave out stay until an answer that withholds nothing (`GitHubSearchResult.isComplete`), so a withheld result that returns is still read or dismissed. With no result left, the first error's message fails the search, so the folder keeps its items and shows the message, such as one asking to grant the sign-in access to the organization. A failure while `NWPathMonitor` reports no usable network path counts as offline (live folder rule 6), since `gh` tells a lost connection only in words. A response whose errors have the type `RATE_LIMITED` waits until `rateLimit.resetAt`, or 15 minutes without it.

```graphql
query($q: String!, $n: Int!) {
  search(query: $q, type: ISSUE, first: $n) {
    nodes {
      __typename
      ... on PullRequest {
        number title url updatedAt state isDraft reviewDecision mergeable
        repository { nameWithOwner } author { login }
        commits(last: 1) { nodes { commit { statusCheckRollup { state } } } }
      }
      ... on Issue { number title url updatedAt state repository { nameWithOwner } author { login } }
    }
  }
  rateLimit { resetAt }
}
```

- Each node becomes a `LiveItem` whose ID is its `url`, with a `GitHubItem` that keeps its kind, state (open, draft, merged, or closed), repository, number, author, review decision, mergeable state, and check state. The item's detail line is "owner/repo #123 · author".

### Items as tabs

- `LiveFolderReconciler.plan(items:tabs:dismissed:)` compares the folder's items with its tabs, given as `LiveItemTab` values (tab ID, item ID, whether the tab has its page, whether a window shows it, and its title). The plan adds a tab for each listed item that has none and is not dismissed, retitles tabs whose items changed title, removes tabs for items the source no longer lists unless the tab has its page or a window shows it, and orders tabs by the source, with retained tabs for removed items last. A retained tab that later loses its page is removed at the next plan.
- The session applies the plan to the folder. A new tab is pinned, in the folder, with `liveItemID`, a saved page of the item's address and title, and a stand-in at that address in the default engine. Hooks get no `tabOpened` for it, since `BrowserHooks` skips tabs with a `liveItemID`. Item tabs are never marked restored (`isRestored`), at a plan or at a relaunch, so their first load counts as a visit and a file they point at downloads, since the user chose to open them.
- An item's tab without its page requests no icon from the item's host: its stand-in is made without `loadSiteIcon()` at a plan and at a relaunch (`restoreTabs` skips the site icon for records with a `liveItemID`), and requests none when its saved page moves. A folder of links to many sites thus contacts none of them, at any refresh or launch, until the user opens an item. The row shows the folder's icon instead: for a feed, the `/favicon.ico` of the feed's host, which the folder fetches from anyway, loaded once per folder and launch through `FaviconLoader`, or `dot.radiowaves.up.forward` until it loads or without one; for GitHub, the item's state symbol. Once its page loads, the row shows the page's own icon, which an automatic unload keeps.
- Item tabs follow live folder rule 4. Their rows show the item's title while on the saved page unless the user renamed the tab, and Tab Names leaves them unnamed. A GitHub item's row shows, while its tab has no page, a symbol for its state in place of the site's icon: `arrow.triangle.pull` in green for an open pull request and gray for a draft, `arrow.triangle.merge` in purple for a merged one, `xmark.circle` in red for a closed one, `circle.circle` in green for an open issue, and `checkmark.circle` in purple for a closed one. The tooltip shows the detail line, the review decision, the check state, a conflict, and the address.
- `FolderTree` refuses every drop into a live folder and every reordering inside one. Moving an item's tab out clears its `liveItemID`. Moved within the pinned tabs, by dragging, Move to Folder, or another space's symbol, it stays pinned and keeps its saved page; Unpin Tab or a drop among the open tabs makes it an open tab and clears its saved page, as unpinning does (bookmark rule 2). The session then immediately plans the folder again with the stored items, adding a tab for the item marked read.

### Read and unread

- `live-folders.json` keeps, for each folder, when each listed item was last viewed (`viewedAt`). Items seen at the folder's first successful fetch count as viewed then. An item is unread if it has no `viewedAt` or, for GitHub, its `updatedAt` is later.
- A window showing an item tab sets its `viewedAt` to the current time, again when a refresh arrives while it shows the tab, and when it stops showing the tab, so the changes the user made while looking, such as an approval, stay read. Mark as Read sets it, Mark as Unread clears it, and Mark All as Read sets it for every item of the folder.
- The tab's `isUnread` follows the item, so the row shows the existing dot. The folder's row shows the count of unread items after its name.
- After the next successful fetch, `viewedAt` and the dismissed set lose entries for items the source no longer lists, unless GitHub withheld results (GitHub). Show Dismissed Items counts only the dismissed items the source lists.
- A raised item limit adds older items that the lower limit left out. The first success after the raise counts as viewed the items it lists after the last of the earlier items (`LiveFolderState.itemLimitRose`), so the raise brings no dots for old items, while a newer item that arrived meanwhile stays unread.

### Refreshing

- `LiveFolderSchedule` is a pure function of a folder's state, its configuration, the trigger, the moment, and Low Power Mode. It answers whether to refresh now and when the next attempt is due, following live folder rule 6, so tests can drive every rule without timers.
- `LiveFolderService`, on the main actor, owns the store, one `NSBackgroundActivityScheduler` (interval 5 minutes, tolerance 1 minute, utility quality of service) that refreshes due folders, the queue that runs at most four fetches and one `gh` process, and the folders' current fetches. The session registers its live folders with it at launch and after each change, passes the triggers (Arch becoming active, a window showing a space, Refresh Now), and receives each result with the folder's items and read state to plan and apply.
- A refresh records its attempt and outcome: the items and validators on success; the error, the failure count, and the earliest next attempt on failure. `URLError.notConnectedToInternet` and `.networkConnectionLost` record the error without counting it, as does a `gh` failure while the Mac has no network path. Quitting cancels running fetches and ends the `gh` process group; a cancelled fetch records no attempt, so its folder is due at the next launch.

### Storage

- `LiveFolderStore` keeps `live-folders.json` in the app's Application Support folder: a version, and for each folder ID (`LiveFolderState`) the source and item limit its items came with, whether the limit rose since, its last attempt and success, failure count, last error, earliest next attempt, feed validators, feed interval and title, items in source order, the time of the first successful fetch, `viewedAt`, and the dismissed item IDs. It writes on its own queue half a second after the last change, and again at quit.
- A file that does not decode moves to `live-folders.unreadable.json`, and the folders fetch again. After the session loads and whenever a live folder goes, entries for folders that are not live folders in `session.json` are removed, and so are the Keychain items of folders that are not private feed folders, so a deleted folder, space, or Persona leaves nothing behind. While `session.unreadable.json` exists, a `session.json` that did not decode and that the session set aside, only the entries and Keychain items of folders that the session registered and that went are removed, so the folders of the set-aside file keep their read state and private addresses for a repaired file; a Keychain item holds a token that Arch cannot get back. A live folder configuration that does not decode, such as one with a source a later build adds, loads as no configuration, so its folder opens as an ordinary folder with its tabs rather than making the whole file unreadable.

### The module (III.21, built)

- Decisions made while building it:
  - Every kept feed item has an address, so the address stands in for a missing ID and no digest is needed. Of two items with one ID the first counts, so each item has one tab.
  - An Atom title of type `text` keeps a `<` that starts no tag, as in "a < b". RSS titles have no type and often hold escaped markup, so they lose tags as `html` titles do.
  - An RFC 822 date without a zone, or with a zone name Arch does not know, counts as GMT.
  - The backoff doubles the interval for each failure in a row up to 6 hours, never below the interval a feed asks for; a rate limit counts as a failure. Creation and Refresh Now refresh at once, even before a `Retry-After` time or a rate limit reset; the timer and activation wait for it. Activation refreshes a GitHub folder whose next attempt is due, or, while it has not failed, after the 5-minute gap, which Low Power Mode doubles as it doubles every interval.

  - A registered folder that goes takes its Keychain item along, also one that `setPrivateAddress(_:for:folderName:)` wrote for it since its last registering, and a write that fails no longer holds back a cleanup for its folder.
  - A refresh records its attempt, with the time it started, when it ends. One that quitting or a change of the folder cancels, or that ends after its folder went or its source changed, records nothing. Registering also starts waiting folders, since a running folder that goes frees its slot.
  - `gh auth status` that cannot run or passes the time limit counts as signed out, and a missing `gh` as not installed. A host other than letters, digits, dots, and hyphens with an optional port is refused before `gh` runs.

## session.json

- III.16 (version 14, built): `TabRecord.savedPage`. `normalized()` gives a pinned record without one, open or closed, its address and title, when it has an address, and drops it from an unpinned record. `TabRecord.closed` keeps it, so a reopened pinned tab returns with its saved page. ## Interactions with other features

- Sync (V.9): a pinned tab syncs its saved page, the user's name, engine, order, space, and folder, not its current address, which settles open decision 2 of `docs/sync.md`. Folders sync their parent and their live configuration, except a feed folder whose address is in the Keychain, which stays on its Mac (live folder rule 8). Item tabs, `live-folders.json`, and every tab's current page stay on each Mac; each Mac fetches its own items.
- Browser import (V.12, built): each imported pinned tab's saved page is its imported address, and an address counts as already pinned in a space when one of its pinned tabs has it as its saved page, wherever that tab's page went (III.16, built). Folders stay one level deep (bookmark rule 6). An imported folder never merges into a live folder of the same name, since nothing else enters a live folder (live folder rule 4); it becomes an ordinary folder beside it. `docs/import-browsers.md`, Duplicates, says the same.
- Agents (VII.12): agent folders stay at the top level of the open list and hold no folders; their tabs never unload automatically. A folder is ordinary, live, or an agent folder, never two kinds at once. VII.12, III.17, and III.18 may land in either order, and whichever lands later adds the agent cases of unloading and of `FolderTree`. VII.12 was built in a tree without III.17 and III.18, so task III.18.1 in `docs/plan.md` holds those cases, with each change they need, until the three are in one tree. With their tests: `TabCloseAction`'s forget for an unkept agent tab on every close path, Delete Persona closing agent tabs without the closed list, `FolderTree`'s refusal of a move into an agent folder or of a folder into one, and the unloading exclusion.
- Web extensions: a tab without its page is left out of the windows the host reports, as a restored tab is today, so unloading a tab removes it from the extensions' view until it loads again. An extension's `tabs.remove` goes through `TabCloseAction`, so it unloads a pinned tab and dismisses an item (Unloading).
- AI hooks: unloading posts nothing; item tabs post no `tabOpened`; Tab Names does not name item tabs.
- The palette and the tab switcher list tabs without pages, as they list restored tabs, so the palette finds feed items and pull requests by title.
- History: refreshing records no visits. A pinned or item tab records a visit when the user opens its page.
- Split view: unloading or dismissing a pane's tab takes it out of the split view, as closing does.
- ⌘-numbers, Next and Previous Tab, and Close Other Tabs treat item tabs as pinned tabs. Archiving never closes pinned tabs, so it leaves item tabs alone.
- Small windows: a small window's tab is never pinned, so none of this applies there.

## Risks

1. Older builds drop the new fields (see session.json). Pinned tabs then get their current pages as saved pages, and live folders become ordinary folders.
2. GitHub's GraphQL schema can change. A query that fails shows its error on the folder row, and the folder keeps its last items.
3. Feeds vary. A malformed item is skipped, and a malformed file is an error that keeps the last items.
4. A feed that gives its items new IDs at every fetch marks them unread each time and replaces their tabs. The item limit bounds the churn.
5. Twenty folders of 50 items make 1,000 tabs without pages in `session.json`. They hold no engine pages, collapsed folders draw no rows, and the limits bound the file.
6. A Chromium tab loses its back list when it unloads, as at a relaunch, and memory pressure can unload every Chromium tab that no window shows (open decision 5).
7. A private feed whose token sits in its path rather than its query is kept in `session.json` and syncs, since Arch cannot tell it apart (live folder rule 8).
8. A tab that plays sound only through Web Audio or a media element outside its document, as many games and some web radios do, can unload while it plays, since neither engine's media script sees that sound (bookmark rule 5). The Settings ▸ Sidebar footer says so.
9. A Chromium tab that a window starts to show while an automatic unload waits for its page's answer to `tryToClose` still unloads if the page then agrees, since CEF is already closing the browser, and it loads again at its last address without what the user did there meanwhile. The page answers at once unless its renderer is busy. CEF has no public way to run a page's `beforeunload` handlers without closing it; a change in `arch-chromium` that asks without closing would let the unload check the windows again before it closes.

## Open decisions

Until the user decides otherwise, the implementation uses the option this note describes.

1. Other sources, such as calendars and documents: none yet (this note); a later plugin contribution in `docs/plugins.md` could add sources that a plugin fetches.
2. JSON Feed: not read (this note); it can join `FeedParser` later.
3. Notifications for new items: none (this note); the dots and counts are enough for now.
4. Requests to the user's teams in Review Requests: left out (this note); a search with `review-requested:@me` includes them.
5. Chromium back lists across an unload: lost (this note), since CEF has no public API that restores navigation entries; a change in `arch-chromium` could add one for unloaded and restored tabs alike.
