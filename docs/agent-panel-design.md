# Agent panel redesign record

This design covers the panel in row VII.34. Its shared parts and view changes were implemented after this proposal. The panel remains a trailing column at `PageReaderColumn.width` in a main or small window. A destination with a known space is named "Persona / Space".

## States

| State | Earlier layout | Earlier technical text | Proposed layout and main action |
| --- | --- | --- | --- |
| Empty | A new composer with a task field, destination, mode, model, and setup guidance when no model is available. | Provider and model choices, access mode, and sometimes tool setup instructions. | Put the task field first. When setup is required, make **Open Providers** or **Open Features** the main action. Keep the destination visible; put the explanation of model requirements in Help. |
| Composing | A scrolling task field, attachment chip, optional excerpt and permissions note, destination, mode, model, effort, warnings, and a fixed Start button. | Mode, model, effort, provider setup, and instruction-file warning. | Keep the task and reviewed attachment above the fold, with **Start** fixed at the bottom. Show "Persona / Space" beside the attachment. Put mode, model, effort, and the excerpt preview in a collapsed Options section; preserve the permission and changed-page warnings beside the affected control. |
| Running | Title, model, place, status, mode, shared tabs, scope, Stop, transcript, queued messages, and a message field. | Model/provider details, mode, site scope, tool handles, usage and tokens, and step failure codes. | Lead with the latest reply and a compact progress sentence. **Stop** is the main action. Keep the next message field fixed at the bottom. Collapse older steps and put mode, model, scope, usage, and Shared Tabs in session details; leave a pending safety decision visible. |
| Waiting on a card | The card follows transcript items and scrolls into view. It shows the host's action, client name, rule codes, optional capture and exact text, the agent's explanation, inputs, and answer buttons. | Rule names or codes, client identity, tab handles, exact target data, and sometimes provider errors. | Pin the pending decision above the message field, headed by the action and site or tab. Its main action is the specific **Answer**, **Share**, **Done**, or **Allow** offered by that card; keep a visible refusal or cancellation action. Keep exact text, highlighted capture, and secret warnings fully visible before the decision. Put rule explanations under an optional disclosure, never hide a material target or permission consequence. Preserve the existing pointer and authentication checks. |
| Taken over | A note says the user took over; Hand Back appears in the header, while the transcript and message field remain. | Mode, scope, model, and status continue to appear. | Show a persistent "You are in control" strip above the transcript. **Hand Back** is the main action. Keep the affected tab reachable and move model, mode, and scope into session details. |
| Ended | The transcript remains; the field is disabled and the session menu still offers deletion and sometimes Keep Tabs. | Model, status, mode, usage and tool details remain in the header or transcript. | Show a short end status and preserve the reply and history. **New Agent Task** is the main action. Put Keep Tabs and Delete Session in the existing actions menu; keep usage under each turn. |
| Failed | An error row appears in the transcript with one action such as Retry, Sign In, or Open AI Settings; field errors appear above the message field. | Provider errors, model names, tool status, and failure text may be exposed. | Place the actionable error above the field with its cause in plain language. **Retry**, **Sign In**, or **Open AI Settings** is the main action according to the existing error action; leave the unsent task or message intact. Put diagnostic detail under a disclosure without hiding an approval or security warning. |

## Reusable parts and visual rules

- Keep the column's 40-point header, 14-point horizontal content inset, 13-point semibold title, 13-point body, 12-point supporting copy, and 11-point secondary detail already used by `AgentPanelColumn`, `AgentComposer`, and `AgentSessionPanel`.
- Use the existing attachment chip, transcript row, approval card, and session action menu. Reuse `SiteSettingsGroup` and `SiteSettingsRow` as visual models for options and details: 32-point minimum row height, 10-point horizontal row inset, 18-point icon column, 8-point icon gap, and 10-point corner radius. Do not move site settings code into the Agent module.
- Primary text uses `.primary`; labels, steps, and metadata use `.secondary`; failures use the existing red role; a sensitive pending decision retains the orange border and a secret warning retains red semibold text. Preserve selection, keyboard focus, accessibility labels, and the page's current background roles.
- A disclosure may hide explanations, prior steps, or settings. It must not hide the current task, destination, selected attachment, requested target, exact text to send, pending choice, or security warning.

## Review before implementation

The initial review called for checking the seven states at the narrow column width, with a long title, long task, multiple queued messages, a large capture, and VoiceOver. The current implementation still needs an app-level review of those cases.
